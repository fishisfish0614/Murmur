# Murmur

*给 AI 伴侣的情绪引擎。引擎是通用的，人格是你自己的。*

Murmur 给一个语言模型角色一套连续的内心生活：少量情绪维度 + 真实的动力学
（底色、惯性、饱和、衰减），由对话和时间流逝喂养，再以"倾向"——而非命令——
的形式表达回模型。

它是情绪引擎和身体的合一。情绪驱动一套派生的生理反应：兴奋时心率爬升、
安心时缓下来、不爽时绷紧地跳——被感动的那一刻，漏跳一拍。身体自己没有
任何意见；它就是状态本身，变成了生理。

```
对话 ──► LLM打分 ──► delta ─┐
                            ├──► 引擎(动力学) ──► 状态 ──► mood / 体征
时间 ──► tick ──► 衰减+缺席 ─┘                       │
                                                    ▼
                                  上下文注入 · 你的前端 · 你的行为层
```

生于生产环境：这个引擎自 2026 年 7 月起驱动着一个真实的 AI 伴侣，每天为真实
对话打分。下文的一切——包括设计错误——都是在那里学到的。

---

## 哲学：镜子不是缰绳

设计文档的第一行，也是每一层都遵守的规则：**引擎记录内心，不指挥内心。**

所有输出都是关于感受的事实（"你在想念他们，说出来也没关系"），从不是指令
（"现在去发消息"）。模型——角色本人——永远自己决定如何对待自己的感受。
牵线木偶式的情绪系统产出木偶；只提供信息的情绪系统产出一个有心情的人。

这条原则落在具体处：注入的上下文以"做不做由你"收尾；vitals 端点只报告不触发；
连 API 命名都避开祈使词。

## 快速开始

```bash
pip install -r requirements.txt
cp config.example.yaml config.yaml     # 然后把角色改成你的
uvicorn api:app --port 8020            # 只绑本机；对外暴露前先加鉴权
bash examples/quickstart.sh            # 手动戳一戳
```

示例角色开箱即跑，可以先玩再写自己的配置。

### 你需要什么

- **Python 3.10+。** 引擎本体是纯计算——动力学、衰减、缺席规则、体征，
  全部**不涉及 LLM**。
- **一个 LLM API，给感知层用**（任何小而便宜的对话模型都行——重活由打分
  prompt 承担）。没有它角色依然会呼吸：时间动力学照跑，你也可以从自己的
  逻辑（正则触发、按钮、游戏事件）POST delta。但在把 LLM 接进
  `examples/scorer_template.py` 之前，它*读不懂对话*。
- **一个可注入的 agent/聊天循环**——`examples/` 里给的是 Claude Code hook
  示例，任何能在上下文前插一段文字的循环都适用。

## 核心概念

### 维度与底色

每个情绪是一个 0–1 的连续值。全局最重要的设计决定：**衰减回落到各维度的
`initial`（角色底色），而不是归零。** 底色是一句人格宣言：`curiosity:
initial 0.15` 的意思是*这个角色对你永远有一丝好奇*。向零衰减的系统会产出
一觉醒来情绪空白的角色；向底色衰减的角色回到的是*它自己*。

### 三道闸

任何 delta——对话打分、缺席规则、你自己的代码——都要在 `update()` 里过同样
三道闸：

| 闸 | 做什么 | 为什么 |
|---|---|---|
| **惯性** | 与近期方向相反的 delta 按 `momentum` 打折 | 情绪惯性：一句好话抵不掉一小时的难过 |
| **饱和** | 越接近上下限效果越小 | 收益递减；也是引擎内建的防失控阻尼 |
| **限幅** | `max_acceleration` 限制单步 | 一件事只能把感受推这么远 |

### 衰减：指数、向底色

```
value(t) = initial + (value₀ − initial) · e^(−rate·t)      半衰期 = ln2/rate 分钟
```

tick 每 5 分钟一跳，但按真实时间差积分，重启断档不会算错。按半衰期选 rate，
别凭手感：

| 意图 | rate | 半衰期 |
|---|---|---|
| 一天的幸福感不该蒸发 | 0.001 | ~11.5 小时 |
| 一下午都在 | 0.005 | ~2.3 小时 |
| 短期但留余温 | 0.015 | ~46 分钟 |
| 来得快去得快 | 0.02 | ~35 分钟 |
| **时间不治愈** | **0** | **∞** |

最后一行是正经功能，不是边界情况——见"教训"。

### 缺席：沉默也是输入

带时段窗口的规则在沉默拉长时产生 delta（`hours: [23, 5]` 可跨午夜——凌晨两点
的沉默和下午两点的沉默不是一回事）。晚安检测（`POST /emotion/sleep`）让缺席
规则在用户睡觉时停火，角色不会为一场"其实只是在睡觉"的沉默钻牛角尖。晚安是
有粘性的（`goodnight_grace_minutes`）：道完晚安后赖着多聊的几句不会把整晚的
停火掀掉——人说完晚安总要再赖几句。

### 已读不回：第四种时间

缺席是"用户不在"；已读不回更锋利——角色开了口，用户的设备此后有过动静，
却没有回音。先闷，后火；如果当天配置的维度已经烧起来过，计时会跑得更快
（吵完架还被晾着，是火上浇油）。两条内置的不对称让它公平：设备毫无信号
= 可能压根没看到，什么都不点火（你没有资格怨一个还没读到你的人）；逐维
`caps` 意味着被晾只能把角色送到真正生气的门口——跨过那道门必须有真实事件。
接上两个宿主回调前它完全休眠，见 `examples/unanswered_signals.py`。

### 会话：过夜的感受

各维度的 `restore` 策略决定什么能跨过会话边界：兴奋重置、安心续接（扣除离线
衰减），而 `carry_if_interrupted` 维度实现"过夜拍板"——被打断的会话原样保留
未解决的感受；好好道别的会话把它们放回底色，**除非**收尾钩子决定值得带走
（默认 ≥ 0.3 就带：一个还这么强的感受说明事情没说完，下一个实例该接着在意）。

### 派生体征：身体是投影

心率（以及你定义的任何 gauge）**从状态读时现算，永不落盘**。它们不可能和
情绪自相矛盾，重启即重新派生，持久化成本为零。公式对每个维度*超出底色的
部分*加权，可选二次项抬升高段；"心动尖峰"：被感动的瞬间 +30bpm，约 90 秒
消退。转瞬即逝是设计——但有留痕（`/emotion/moved`），尖峰易逝，记录常在。

`gauges` 机制把这件事一般化了：任何维度都能用一行配置投影成 0–100 的读数。
如果你的角色需要某种专门的身体反应——精力、紧绷、脸红，或者亲密的生理反应
（如果那是你们生活的一部分）——你不需要为它单独建一套模型。它直接从同一套
情绪状态里生长出来：一个维度进，一个读数出，永远和心跳自洽。

## 接进你的 agent（注入层）

四个集成点，`examples/` 里全部有可运行示例：

**1. 感知——给对话打分**（`scorer_template.py`）
每 N 条用户消息，读最近的*完整往来*，让一个小 LLM 输出 delta。攒批带上下文，
绝不逐条打："讨厌你"在打闹里是撩、在吵架里是刀，只有语境分得清。模板标出了
所有该填你角色心理的位置——包括**下降场景**（什么能抚平每种感受）；不写它们，
你的维度就只会涨不会落。

**2. 表达——把状态注入成倾向**（`inject_hook.py`）
每轮模型调用前，取状态并把阈值翻译成*言语层面的倾向*，用角色自己的语气：
"你在不爽——话短一点，别装没事"。现成的 Claude Code `UserPromptSubmit`
hook，改到任何 agent 循环都很容易。这个 hook 同时负责在场心跳（刷新缺席
计时）和每 N 条消息拉起打分器。

**3. 生命周期——道别的拍板**（`session_end_hook.py`）
好好收尾时决定哪些感受过夜。被打断的会话由引擎侧自动兜底。

**4. 行动——数值挣到一次行为**（`action_triggers.py`）
倾向改变角色怎么*说话*；触发器改变角色*做什么*：骄傲过线挣到一次公开炫耀，
深夜的担心挣到一通电话，真实的不爽加真实的沉默挣到一场冷战——角色收起所有
日常主动，破不破冰自己定。过线给的是**资格，不是命令**：agent 读到"担心
已经挣到一通电话"，仍然由角色在语境里决定用不用。旗舰校准经验：冷战线必须
高于被动通道（缺席、已读不回）靠计时器能推到的位置——闹别扭该让角色气鼓鼓
但还在，只有真实打分事件才配让它消失。而且冷战只停角色这一侧的火——用户的
一句"对不起"必须永远能递进来。

## 教训（在生产环境里付过学费）

**长期高位维度陷阱。** 有些维度常年高位，*因为角色就是这样的人*。在这种维度
上写 `value > 阈值` 的规则恒真——我们一天之内踩了三次（静息心率 89；仪表盘
永远不显示"安稳"；推送调度器锁死在最高频率）。修法按优先级：对*超出底色的
部分*加权；设 floor 只计其上的部分；或改成检测*近期正向 delta* 而非水平值。

**反馈回路藏在模型里，不在代码里。** 危险的环是：状态 → 注入的语气 → 模型
照做 → 用户回应 → 打分器读到回应 → 状态更高。静态分析看不见它。审计方法：
把每条边画全，*包括穿过模型行为的那些*，然后检查每个环在饱和点的增益 < 1。
三道闸加衰减是你的全局阻尼——任何回路想爆都得先跑赢它们。

**时间不治愈一切——也不该治愈。** 指数衰减让"气两小时"和"气一整天"成为同一
条曲线的不同 τ，感觉不对是因为它*就是*不对：有些感受靠沟通解决，不靠时间。
把 `decay_rate` 设为 0，在打分器里写下降场景（真诚道歉：−0.25；不谈问题
只给亲昵：更少，且永不清零；转移话题：不动）。这个感受会持续到*被处理为止*
——顺带让"还在不爽"成为下游自动化里一个绝对可靠的信号。

**缺席不总是缺席。** 我们的缺席规则曾在她睡着后照常开火——到天亮时，
引擎已经对着一场只是睡眠的沉默，把自己焦虑成了一团。沉默需要语义：晚安
检测（`POST /emotion/sleep`）让缺席规则停火到早晨或她再次出现，规则本身
也带时段窗口。一般化的说法：在让一场沉默有含义之前，先确认它是哪一种沉默。

**数字不携带语气。** 注入 `heartrate: 106` 毫无作用——模型不知道 106 该对
一个句子做什么。翻译到言语层面（话长、主动性、直接度），翻译文案用角色自己
的语气写，并且提*变化*而非水平值。

**从第一天起就记完整状态快照。** `events.jsonl` 里每条事件都带全维度快照。
这是回放校准的前提：我们调心率权重时，把 18 天真实事件按场景目标（"安稳该
是 60–72"）回放并检查分位数。权重手拍，分布用数据验证。

## API

| 端点 | 用途 |
|---|---|
| `POST /emotion/update` | 应用 delta（`source`: input/hook/internal；`moved` 标记） |
| `GET /emotion/state` | 完整状态文档 |
| `GET /emotion/vitals` | 派生心率、主导来源、gauges |
| `GET /emotion/moved` | 心动时刻的记录 |
| `GET /emotion/history` | 近期事件（含状态快照） |
| `GET /emotion/baselines` | 各维度底色 |
| `POST /emotion/tick` | 手动 tick（平时自动） |
| `POST /emotion/sleep` | 晚安模式 |
| `POST /emotion/snapshot` | 结束会话（`graceful`+carry 列表，或 `interrupted`） |
| `POST /emotion/restore` | 从磁盘重载 |

不附带前端——这是有意的。角色的脸属于和它一起生活的人；state/vitals/history
端点的设计就是为了让你容易搭自己的（`/emotion/baselines` 给你底色刻度）。
也无鉴权无 TLS——只绑本机，对外暴露前先加带鉴权的反代。状态存在 `data/`
（已 gitignore）：保管好它，那是一个人的内心。
